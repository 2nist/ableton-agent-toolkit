# Progression Studio

A data-driven chord progression builder for Ableton Live — Phase 2 of the
Progression Studio project (Chord Assistant v2).

Right-click a **MidiTrack** or a **Session clip slot** → **Open Progression Studio**
or **Generate Melody** → one shared webview modal opens with:

- **Tension-colored progression canvas** — each chord card is colored by the
  hybrid functional+empirical tension model (`@platform/progression-engine`),
  with a live tension curve strip above.
- **Build / edit** — add, remove, reorder, duplicate chords; per-chord
  **degree**, **quality** (maj / min / 7 / maj7 / min7 / m7b5 / dim / aug /
  sus2 / sus4), and **duration** (1–16 beats). Whole-progression transposition
  via ♭ / ♯.
- **Corpus-ranked suggestions** — "next chord" chips (top 7 with probabilities)
  and **top paths** (beam-searched continuations) from the transition model
  trained on 17,527 lead-sheet sections.
- **Matching songs** — as you build a progression, the **Matching songs (lead
  sheets)** panel lists songs from the lead-sheet corpus whose section plays
  that progression as a contiguous run (key-invariant), e.g. `I V vi IV` →
  Alicia Keys - No One, Taylor Swift - Eyes Open, … The index
  (`song_sections.json`, 7,980 song-like sections from 5,877 artist–title
  pairs) is gzipped into the modal and decompressed client-side.
- **Bi-tonal color layer** — a **Color** select in the header layers a
  bi-tonal chord above the progression (from `@platform/progression-engine`'s
  `generateBiTonal`): Instrument A stays the low sustained anchor; Instrument B
  is a chord on the shifted root up high, voice-led toward the previous color
  chord and syncopated (conversational pattern). Flavors are intentionally
  ambiguous — just one word: **Shimmer** (maj +5th → Maj9), **Wonder** (maj
  +2nd → Maj13(#11)), **Drama** (maj +7th min → Maj9(#11)), **Glow** (min +m7 →
  m11), **Ocean** (min +5th → m9), **Tension** (7 +b2 → 7(b9#9#11)).
- **Melody layer** — a **Melody** checkbox (with a **Density** select: smooth /
  medium / flowing / dense) adds a monophonic line riding the progression,
  generated by `@platform/progression-engine`'s `generateMelody` (see below).

All three layers (chords, melody, bi-tonal color) are generated from **the same
modal controls** — check Melody and/or pick a Color flavor, then Render once.
**Each layer lands on its own instrument**: the anchor block chords stay on the
track you right-clicked; the melody and the bi-tonal color each go on a newly
created MIDI track directly below it (named `… · Melody` and `… · <flavor>`).
In a Session slot they merge into one self-contained clip.
- **Presets** — all 23 `@music-theory/core` presets load instantly.
- **Live-aware** — the modal is seeded from Live's current scale root: the
  **Key** select defaults to `Song.rootNote` (via a **Live key** checkbox), and a
  readout shows Live's key · scale · time signature (e.g. `A · Minor · 4/4`).
  The time signature is read from the song's first scene (SDK 1.0.0 exposes it
  per-`Scene`, not on `Song`); Live reports an unset scene signature as `-1/-1`,
  which is sanitized back to `4/4`.

**Render to Live & Close** sends the progression back. Where the clip lands
follows what you right-clicked:

- **MidiTrack** → the anchor chord clip on the right-clicked track, then a
  new MIDI track below for the melody (when on), then another below for the
  bi-tonal color (when a flavor is picked).
- **ClipSlot** (Session view) → one clip created directly in that slot. Every
  enabled layer (chords + melody + bi-tonal color) merges into that single
  self-contained clip.

Note: the modal's `live` payload and every numeric field are `Number()`-coerced
(and `JSON.stringify` is BigInt-safe) because Live's native layer surfaces some
values (rootNote, scene signatures) as BigInt — a raw BigInt used to crash the
modal with "Do not know how to serialize a BigInt".

The **Generate Melody** context action simply opens the same modal with the
Melody checkbox pre-checked — it's no longer a separate editor. The melody is
generated by `@platform/progression-engine`'s `generateMelody`, trained on the
Tegridy/LA general-MIDI corpus (`melody_model.json`, ~1.4M melody notes):
per-chord melody-interval distributions + a melodic-contour Markov chain, so
every note is a chord tone of its chord and the line stays stepwise/singable.

## Session vs arrangement

Both context actions register on `MidiTrack` **and** `ClipSlot` scopes. The
handler resolves the handle and branches: `instanceof MidiTrack` renders to the
arrangement; `instanceof ClipSlot` renders into that Session slot. Arrangement
melody mode makes two clips (chords, then melody); Session mode merges them into
the one clip a slot can hold.

## Architecture

- `src/webview/app.ts` — the studio UI (typed TS, imports the engine directly).
  Bundled by `build.ts` to a single IIFE and inlined into the modal page.
- `src/studio.ts` — composes the self-contained modal HTML (`Ui.showModalDialog`).
- `src/render-progression.ts` — pure: studio result → `NoteDescription[]`,
  plus `renderMelodyResult` (chords → melody notes) and `renderBiTonalResult`
  (anchor + color voices) via the engine.
- `src/generated/studio-bundle.ts` — **generated** by `build.ts` (bundled app +
  embedded `transition_model.json` / `tension.json` / `melody_model.json` /
  gzipped `song_sections.json` / presets). Don't edit.
- Corpus data comes from `@platform/progression-engine`'s `data/` (run its
  `npm run build:model` for the transition model, `npm run build:melody` for
  the melody model, `npm run build:songs` for the song index, after the
  corpus grows).

## Build / test

```sh
npm run build        # typecheck + bundle webview & extension
npm test             # render-progression unit tests
```

Note: `@platform/progression-engine` must be built first (`npm run build` in
that package); the extension bundles the engine's TS source for the webview.
